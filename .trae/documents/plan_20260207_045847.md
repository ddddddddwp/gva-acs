# TR069 插件完整架构与实施方案

本方案旨在实现 **GVA (Gin-Vue-Admin)** 与 **TR069 协议** 的深度集成。插件将作为一个独立的模块运行，拥有独立的端口监听能力，同时复用 GVA 的基础设施（数据库、日志、配置管理）。

---

## 1. 核心架构设计

### 1.1 角色分工

*   **Host (GVA Server)**:
    *   **职责**：提供运行时环境、数据库连接池 (GORM)、统一日志 (Zap)、配置管理 (Viper)。
    *   **端口**：`8888` (管理 API)。
*   **Plugin (TR069)**:
    *   **职责**：启动独立的 HTTP Server，处理 TR069 协议交互，管理设备生命周期。
    *   **端口**：`7547` (CPE 交互专用，可配置)。
*   **Library (TR069 Core SDK)**:
    *   **职责**：纯粹的协议解析与构建 (XML <-> Struct)。无状态，不涉及 IO。

### 1.2 数据流向 (Pipeline)

1.  **CPE Request** -> `Plugin Server (:7547)` -> `Gin Handler`
2.  `Gin Handler` -> **Read Body** -> `SDK Parser` -> `Message Struct`
3.  `Message Struct` -> `Plugin Service` -> **Business Logic (DB CRUD)**
4.  `Plugin Service` -> `Message Struct (Response)` -> `SDK Builder` -> `XML Bytes`
5.  `XML Bytes` -> `Gin Handler` -> **HTTP Response** -> **CPE**

## 3. 核心模块实现细节

### 3.1 插件入口 (`plugin.go`)
实现 `plugin.Plugin` 接口，负责在 GVA 启动时：
1.  读取 `config.yaml` 中的 `tr069` 配置。
2.  执行 `initialize.Gorm()` 进行数据库自动迁移。
3.  调用 `initialize.StartTR069Server()` **异步启动** 7547 端口监听。
4.  注册 GVA 管理侧的 Router (8888 端口)。

### 3.2 独立服务启动 (`initialize/server.go`)
```go
func StartTR069Server() {
    // 读取配置端口，默认 :7547
    addr := global.Config.Address 
    
    // 创建独立的 Gin Engine
    engine := gin.New()
    engine.Use(gin.Recovery()) // 崩溃恢复
    
    // 注册核心 Handler
    engine.POST("/", handler.CWMPHandler)
    
    // 异步启动，避免阻塞主进程
    go func() {
        if err := engine.Run(addr); err != nil {
            global.GVA_LOG.Error("TR069 Server 启动失败", zap.Error(err))
        }
    }()
}
```

### 3.3 协议适配 Handler (`handler/cwmp.go`)
```go
func CWMPHandler(c *gin.Context) {
    // 1. 获取 SDK Parser
    p := factory.NewParser()
    
    // 2. 解析请求
    body, _ := io.ReadAll(c.Request.Body)
    msg, err := p.ParseMessage(context.Background(), body)
    if err != nil {
        c.Status(400)
        return
    }
    
    // 3. 路由到 Service 层处理
    // Service 层会根据 msg.Method (如 Inform) 执行不同逻辑并返回响应结构
    respMsg, err := service.ServiceGroupApp.CWMPService.HandleMessage(msg)
    
    // 4. 构建响应
    b := factory.NewBuilder()
    respBytes, _ := b.BuildMessage(context.Background(), respMsg)
    
    // 5. 返回
    c.Data(200, "text/xml", respBytes)
}
```

## 4. 扩展性说明

*   **多协议支持**：未来如果需要支持 MQTT，只需复制 `initialize/server.go` 和 `handler/` 目录，修改端口和解析逻辑，即可在同一个插件内（或新建插件）并行运行。
*   **配置化**：端口、认证信息均从配置文件读取，不硬编码。
*   **业务解耦**：SDK 只管解析，Service 只管业务，Server 只管网络。
