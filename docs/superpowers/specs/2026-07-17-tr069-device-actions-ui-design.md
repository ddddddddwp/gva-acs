# TR-069 设备操作区 UI 设计

## 背景

设备列表当前将“同步参数”“参数”和“更多”并列展示。“更多”承载查询、配置、文件、维护以及删除设备，入口过于集中；同时 `el-dropdown` 与相邻 `el-button` 使用不同的行内基线规则，造成三个入口不在同一水平线。

本次调整重新组织操作入口，同时保持 GVA/Element Plus 的链接按钮、下拉菜单、抽屉和主题风格。

## 设备列表操作区

操作列固定展示四个入口：

```text
参数    查询与配置⌄    文件与维护⌄    删除
```

- 使用一个 `inline-flex` 容器，统一垂直居中、间距和不换行行为。
- “参数”“查询与配置”“文件与维护”继续使用 `primary link` 风格。
- “删除”使用独立的危险色链接入口，明确区别于 CWMP `DeleteObject`。
- 操作列只按容纳四个入口所需的宽度扩展，不改变其他表格列。

## 参数入口与抽屉

点击“参数”直接打开现有参数树抽屉。“同步参数”不再占用设备列表操作列，改为参数抽屉顶部的设备操作。

抽屉头部保留设备序列号和在线状态，右侧依次显示：

- `刷新本地数据`：重新读取 GVA 数据库中已保存的参数树，不发送 CWMP RPC。
- `同步设备参数`：下发一次完整的 `GetParameterValues`，参数路径为 `Device.`。

设备离线时仍允许查看和刷新本地参数，但禁用“同步设备参数”。同步期间按钮显示加载状态，重复点击不会创建第二条命令；创建成功后提示 `commandId`，完整进度仍由 RPC 记录页面承载。

同步逻辑由参数抽屉组件负责，设备列表只负责传入当前设备，不保留抽屉内部的同步状态。

## 查询与配置菜单

菜单使用不可点击的灰色小标题和分隔线：

```text
查询
  查询设备能力
  获取参数
  获取参数名称
  获取参数属性
────────────
配置
  配置参数
  配置参数属性
  添加对象
  删除对象实例
```

`删除对象实例` 对应 CWMP `DeleteObject`，只修改用户可见名称，不改变方法名、请求结构或权限标识。

## 文件与维护菜单

```text
文件
  下载文件
  上传文件
────────────
维护
  重启设备
  恢复出厂设置
```

## 状态、权限与危险操作

- 离线设备禁用全部主动 CWMP 操作，但仍可查看本地参数和删除 GVA 中的设备记录。
- 除“查询设备能力”外，RPC 入口继续根据设备声明的支持能力禁用。
- `删除对象实例`、`重启设备`和`恢复出厂设置`继续使用既有危险操作二次确认。
- 独立的“删除”仅删除 GVA 设备记录，并继续使用现有删除确认，不与 CWMP `DeleteObject` 混用。
- 本次不改变 API、Casbin 权限、RPC 表单、命令状态机或记录页面。

## 主题与视觉约束

- 使用 Element Plus 组件和 `--el-*` 主题变量，不硬编码亮色或暗色背景、文字和边框颜色。
- 下拉分组标题沿用现有 `rpc-group-title` 风格。
- 操作列的链接按钮保持相同字号、行高和垂直中心线。
- 参数抽屉保留现有 GVA 表面色、边框、树和表格布局，只调整头部按钮名称和增加同步入口。

## 测试与验收

- 契约测试验证操作列只包含四个顶层入口，且统一放入行内 flex 容器。
- 动作定义测试验证两个组合菜单的分组、12 个 CWMP 方法以及 `删除对象实例` 文案。
- 参数抽屉契约测试验证“刷新本地数据”和“同步设备参数”的位置、离线禁用、`Device.` 同步参数和重复提交保护。
- 运行全部 TR-069 前端测试及生产构建。
- 在亮色和暗色主题下人工确认四个入口同一水平线、菜单分组清晰、抽屉按钮可辨识。
