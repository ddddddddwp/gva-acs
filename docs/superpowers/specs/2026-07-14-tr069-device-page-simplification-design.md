# TR-069 设备页简化设计

**日期：** 2026-07-14  
**状态：** 已完成交互设计确认，待书面规格复核  
**范围：** GVA TR-069 插件设备列表、参数同步入口、参数树查询和命令下发前置条件

## 1. 目标

简化 TR-069 设备列表的操作路径，移除低频和重复入口，使日常操作集中为：

1. 对在线设备快速触发一次完整的 `GetParameterValues(Device.)`。
2. 从设备列表打开现有参数树，查询最近一次同步形成的数据库缓存。
3. 将自定义 GPV 和 SPV 保留为低频扩展操作。

本次不重新设计参数树布局，不新增左侧菜单，不增加任务进度页面。

## 2. 当前问题

- 设备操作分散在列表、详情抽屉和参数树抽屉中，日常入口较深。
- 详情抽屉同时承载基础信息、RPC 刷新、GPV、SPV、全量同步、参数树和 TR-196 参数，职责过多。
- “刷新 RPC”和 TR-196 参数区不属于当前首要工作流。
- 参数树顶部的“全量同步”与设备列表快捷同步重复。
- 参数树使用 `row.status` 判断在线状态，但设备接口实际返回 `row.online`。
- 命令队列依赖 Redis，而当前本地配置为 `system.use-redis: false`，现有下发入口无法正常工作。
- 当前页面只提示任务已下发，不展示任务完成状态；本次明确保持这种轻量反馈。

## 3. 页面结构

### 3.1 保留内容

设备列表继续保留：

- 序列号搜索与重置。
- 白名单设备录入。
- 设备表格、分页和在线状态。
- 删除设备与二次确认。
- 现有自定义 GPV、SPV 表单。
- 现有参数树大抽屉、左树右表、节点搜索和缓存刷新。

### 3.2 删除内容

- 设备详情抽屉及其全部模板、状态和处理函数。
- “刷新 RPC”入口。
- TR-196 基站无线参数区和 `FapInfo` 页面依赖。
- 详情中的独立全量同步入口。
- 参数树顶部的“全量同步”入口。
- 新增左侧“参数树”菜单的方案。

### 3.3 操作列

设备列表操作列统一为：

```text
同步参数 | 参数 | 更多 ▼
                  ├─ 获取参数
                  ├─ 配置参数
                  └─ 删除设备
```

#### 同步参数

- 仅在线设备可用。
- 直接创建一条 `GetParameterValues` 命令，唯一参数路径为 `Device.`。
- 不弹出路径选择或确认对话框。
- 成功后只显示“同步任务已下发”。
- 使用行级 loading 防止同一设备重复点击。

#### 参数

- 在线和离线设备均可用。
- 打开现有参数树抽屉。
- 只读取数据库缓存，不触发 CWMP 命令。

#### 获取参数

- 放入“更多”下拉菜单。
- 复用现有自定义路径 GPV 弹窗。
- 仅在线设备可用。

#### 配置参数

- 放入“更多”下拉菜单。
- 复用现有 SPV 弹窗。
- 仅在线设备可用。

#### 删除设备

- 放入“更多”下拉菜单。
- 不受在线状态限制。
- 保留二次确认。

## 4. 参数树职责

参数树成为纯查询界面：

- 保留现有右侧大抽屉展示方式。
- 保留左侧树、右侧参数表、节点搜索和复制参数值。
- “刷新结构”重新读取数据库中的参数结构。
- “刷新数值”重新读取当前节点的数据库值。
- 打开抽屉、展开节点、刷新结构或刷新数值均不得向设备下发命令。
- 在线标签统一读取设备接口的 `online` 字段。

参数树由 `tr069_datamodel_values.name` 中以点分隔的完整参数名在前端构建；本次不使用 `GetParameterNames` 递归发现结构。

## 5. 同步数据流

```text
用户点击“同步参数”
  → 前端检查 row.online
  → 后端再次检查设备在线状态
  → Redis 创建一条 GPV(Device.) 命令
  → 尝试 Connection Request
  → 设备在当前或后续 CWMP 会话领取命令
  → 设备返回全部参数叶子
  → core 解析 GetParameterValuesResponse
  → DataModelHook 写入 tr069_datamodel_values
  → 参数树从数据库缓存读取并构建树
```

约束：

- 一次用户操作只创建一条 GPV 命令。
- 参数路径固定为 `Device.`。
- 不发送 `GetParameterNames`。
- 不按节点递归创建命令。
- 不把“任务已下发”解释为“同步已完成”。

## 6. 在线状态与命令准入

在线判定继续使用当前规则：最后一次 Inform 距当前时间少于 180 秒。

- 前端对离线设备禁用“同步参数”“获取参数”“配置参数”。
- 禁用项显示“设备离线，无法下发命令”。
- 后端必须重复在线校验，不能仅依赖前端。
- 离线请求不创建数据库命令记录，也不写入 Redis。
- “参数”和“删除设备”不受在线限制。

该在线状态代表近期收到 Inform，不代表 CWMP 会话当前仍打开。因此命令可能等待下一次 Inform；这不改变本次轻量反馈策略。

## 7. Redis 与 Connection Request

本地运行环境启用已有 Redis：

```yaml
system:
  use-redis: true

redis:
  addr: 127.0.0.1:6379
```

继续复用现有 Redis immediate queue，不新增 MySQL 队列或内存降级队列。

Connection Request 失败不直接让“创建任务”接口失败。只要任务成功写入 Redis，接口返回“同步任务已下发”，设备可在后续 Inform 会话中领取命令。HTTP Connection Request 与当前 HTTPS 限制的适配不属于本次页面简化范围。

## 8. 错误处理

- 设备离线：`设备离线，无法下发命令`。
- Redis 未初始化或不可用：`命令队列不可用，请检查 Redis 服务`。
- 自定义 GPV 没有路径：保留现有表单校验。
- SPV 没有有效参数：保留现有表单校验。
- 命令成功入队：`同步任务已下发` 或现有 GPV/SPV 成功提示。
- 参数树查询失败：保留当前结构/数值查询错误提示。

本次不增加：

- PENDING/SENDING/SUCCESS/FAIL 状态展示。
- 前端轮询。
- 同步进度条。
- 完成后自动打开参数树。
- 完成后自动刷新参数树。

## 9. 组件边界

### 设备列表页

负责设备查询、在线状态展示、操作入口、GPV/SPV 弹窗和参数树抽屉的打开状态。

### 参数树组件

只负责从 GVA API 读取缓存结构和值并展示，不负责命令创建。

### CommandService

负责在线校验、命令数据构造、数据库记录、Redis 入队与 Connection Request 尝试。在线校验应集中复用，避免各 API 产生不同判定。

### DataModelHook

继续负责解析 GPV 响应并持久化参数名、类型和值。本次不改变其职责。

## 10. 验证策略

### 后端自动验证

- 在线设备同步只生成一条 `GetParameterValues` 命令。
- 命令参数严格为单一路径 `Device.`。
- 离线设备返回明确错误且不创建命令、不写 Redis。
- Redis 不可用时返回明确队列错误。
- GPV 响应继续写入 `tr069_datamodel_values`。

### 前端验证

- 执行生产构建，确保删除详情和 `FapInfo` 依赖后无编译错误。
- 在线设备可操作同步、获取参数和配置参数。
- 离线设备的三个下发入口均禁用。
- 参数树和删除操作始终可用。
- 参数树不再出现“全量同步”按钮。
- 参数树在线标签使用 `online` 字段。

### 联调验证

1. 启动 Redis、GVA/TR-069 和 BS/OAM。
2. 等待 BS Inform，使设备显示在线。
3. 点击“同步参数”，确认只产生一条 GPV `Device.` 命令。
4. 等待设备响应，确认 `tr069_datamodel_values` 更新。
5. 打开“参数”，确认参数树读取最新缓存。
6. 停止或等待设备离线，确认所有下发操作禁用但参数缓存仍可查询。

## 11. 非目标

- 不重做参数树视觉布局。
- 不新增 TR-069 左侧菜单。
- 不恢复或重新设计 RPC 方法刷新。
- 不提供命令历史或状态中心。
- 不实现参数同步进度跟踪。
- 不改为 MySQL 或内存命令队列。
- 不在本次处理 HTTP Connection Request 与 HTTPS 强制限制。
- 不修改 TR-069 core XML 可观测性设计；该工作继续作为独立变更维护。
